# 系统架构

```text
用户上传数据
  -> 字段映射与规范化
  -> 数据质量校验
  -> 品牌/门店/平台/周期分组
  -> 确定性规则诊断
  -> 证据与来源行绑定
  -> 候选任务生成
  -> 人工确认与后续验证
```

核心脚本分为三层：

1. `validate_and_calculate.mjs` 校验数据粒度、周期、0 值和核心数值，并计算可复核指标。
2. `execute_rules.mjs` 在可比较范围内执行规则，输出门店优先级、事实和证据。
3. `create_action_loop.mjs` 将规则命中映射为候选任务，补充证据要求、负责人角色、观察周期和验证指标。

`run_takeout_review.mjs` 负责串联三层流程，并生成 Markdown、CSV 和 JSON 结果。

## 多 Agent 深度诊断

```text
用户上传数据
  -> 连锁外卖经营总控选择模式
      -> 轻量模式：直接运行现有完整 Skill
      -> 深度模式：经营数据质检专员
          -> 按品牌—门店切片
          -> 门店经营诊断专员
          -> 经营策略方案专员
          -> 行动合规审核专员
              -> 通过待人工确认 / 待补证据
              -> 退回策略 Agent（最多修正一次）
              -> 安全拒绝
          -> 总控汇总普通报告与协作轨迹
```

四个成员按责任分离，不按平台命名。平台是门店任务内部的分析维度；总控不得修改专业事实或覆盖审核结果。

Agent 间通过结构化交接传递任务范围、事实、证据引用、限制和下一步，不共享无边界的完整对话。`multi-agent/scripts/run_multi_agent_review.mjs` 是可重复测试的本地编排器；它验证协议与确定性业务内核，不声称调用了五个独立语言模型。WorkBuddy 包通过官方专家团结构完成真实成员调度。
